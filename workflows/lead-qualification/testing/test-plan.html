How to read this page
  • Every case sends one situation into the real workflow, says what should happen, and shows what did happen.
  • The case number is a letter for the topic and a number within it: A1 is the first case of group A. The seven groups are listed below.
  • Red cases are error or edge cases, dashed ones needed a real click or a real mail. Problem found, fixed, passed means a test uncovered a defect, it was fixed, and the case then passed.

G2

Ping failure must not cost a lead

problem found, fixed, passed
Test mails, then a real burst
What I sent
Healthchecks refused the start ping when pings came in quick succession.
Should happen
The lead still runs through, the ping hangs as a side branch.Based on: The custom node outputs only {error} on failure, which would replace the lead data in the data path
What happened
Finding in the first run: 8 mails lost (the run ended with {error}). Fix: ping_start hangs in parallel on prepare_email_data. Note

G3

Ping order on the Healthchecks dashboard

problem found, fixed, passed
Real mails, Healthchecks dashboard
What I sent
Open the check 'lead-qualification' on healthchecks.io.
Should happen
Start and success pings are visible, status green.Based on: Custom node Healthchecks Ping
What happened
Finding: with real mails 'OK' came before 'Started' and the duration was wrong (2 min 17 s instead of 16 s). Cause: n8n works through parallel branches from top to bottom on the canvas, ping_start sat below check_lead. Fix: ping_start placed above check_lead. Re-test with a real IMAP mail: Started, then OK, 4 s, status up.
Note
Keep ping_start above the main branch on the canvas, otherwise the order flips again.
